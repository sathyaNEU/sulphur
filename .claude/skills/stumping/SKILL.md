# Stumping

> "A deep task asks for several pieces of genuine analysis spread across the work, each ending in a result that can
> be checked, and more careful work keeps earning more. It is never won or lost on one hidden or planted thing that,
> once caught, flips the whole answer." (`guidelines/client/deep-reasoning.md`)

This skill decides where a task is hard. Work Part 7 first (the draw), then Parts 1 to 6. Read before designing:
`guidelines/client/project-lead-review-2026-11-09.md` (why tasks that passed every check here came back),
`guidelines/client/deep-reasoning.md` (the standard, the fourteen areas, the effort test, the shallow hidden
factor), the strategies for the assigned domain group in `guidelines/client/learning-modules/stumping-strategies.md`
(indexed in `references/sulfur-strategies.md`), and `references/sulfur-record.md` (what the Sulfur runs and reviews
measured). Mark's record behind each caution is `references/evidence.md` and `references/strategies.md`. The note's
shape is `references/design-note-template.md`; `precut.py` reads it and `effort.py` scores it.

**The platform's two runs are the only measurement.** No solver, scored reader or probe runs on any build
(`CLAUDE.md`, the STOP block). `effort.py` is arithmetic on the generator's own implementations of named methods; it
never reads the prompt.

## Part 0. The goal, the opponent, and what changed

**The goal.** The two runs average under 60 on the generated rubric and lose their points for analytical reasons,
in several places; the reviewer reading the design finds no one thing that flips the answer. Build to 50 on paper.

**The opponent, as measured.** Mark's portal record (37 approvals, about 60 returns read in full) and the Sulfur
runs agree on what a frontier run does unprompted: it reads every file and every document and executes any sentence
that names a step; it runs the hygiene battery (duplicates, clocks, re-keyed records, latest versions); it runs the
field's textbook method for each quantity by reflex; it models any pattern that one plot or one group-by of one file
shows (`sulfur-record.md`, five rounds: "noticing was the whole stump"); it holds out, back-tests and bootstraps
(task7 arch 5's run held out 122 pairs and bootstrapped unasked). What it does in a hurry, by the client's table
and our runs: stops at the first account that reconciles, never tests the rival explanation, looks at a handful of
series where the question needs all of them, estimates a quantity and never carries it into the decision, reports
pieces that do not add back to the total, and checks robustness only by varying nearby choices. **Every result that
prices the task lives in that second list.**

**What changed on 2026-11-09.** The project lead returned the pattern this harness built for fourteen builds: one
deep step, hidden in a constructed world, with a ladder of rungs below it and asks coupled to it. Those builds passed
every gate here and still read as one thing, because the deep step was usually a factor the generator put where it
decides. The single-step anatomy (the default path ending on one wrong answer, the stump sentence, the survivor
anatomy, the readability screen, the ladder) is retired as the organising object of a design. What it measured
survives as cautions on each result (Part 5).

## Part 1. The results chain

### 1.1 Start where the difficulty already exists

Real analysis is hard because of how data come to exist: meters change resolution, loggers restart their counters,
cohorts have not finished, sources disagree on keys and totals, hundreds of series move together with noise, two
changes land in one window. Write down the process that produces the files (who records what, when, by which route,
what they cannot see) before any result is named; each result is a place where that process makes honest analysis
long. Generated data is fine when the generator simulates that process (`dataset-generation` §2); public data used
as is is welcome where it fits. Never start from a result and add an effect to produce it.

### 1.2 Decide where the weight sits

Name the place most of the work lives: assembly, measurement, triage, investigation, modeling, validation,
attribution, synthesis, allocation, a hard-to-measure quantity, or a metric or rule to design (`vocab.json`
weights). Pick one not leaned on in the last builds (`guard.py` blocks a repeat of either of the last two). The
client's six weightings in `deep-reasoning.md` ("Vary where the hardness sits") show how different the same depth can
look.

### 1.3 List the checkable results

Each result is a figure, a set, a dated event, a table or a rule that a grader can check against the golden on its
own: the usable runs and the point each was evaluated; the degraded set; the onset and its leading indicator; each
cause's share with the interaction shown; a forecast with its band and backtest error; the reconciled account. For
each, the design note's `## Results chain` row names:

| Column | What it holds |
|---|---|
| Result | the checkable thing, in the deliverable's terms |
| Area | one of the fourteen (framing, data discovery, assembly and reconciliation, missingness and measurement, exploration and triage, investigation loops, modeling, validation, causal reasoning, forecasting, decomposition and attribution, uncertainty, synthesis, self-verification) |
| Pinned by | the data or the stated convention that makes it determinate (`determinism-check`) |
| Band | exact, or the range every defensible method lands in |
| Hurried analyst | the deep class at this result and what a careful run in a hurry files instead |
| Depends on | earlier results, or `independent: <input>` when the result can be graded on an input of its own |
| Graded as | the answer block: Recommendation, Component n, Ask n |

The rules:
- **Four or more results, three or more areas**, each needing its own work. A lookup, one sort or one filter is not a
  result. Six is the client's illustration; more is fine when each is real work.
- **Each result's hurried failure is one the runs make**: method shortcut, unfinished chain, stopped at the first
  story, narrow look at broad data, dismissed own evidence, self-confirming check. A result whose only difficulty is
  the textbook method, a pattern one plot shows, a holdout or a bootstrap is earned by the runs; it may stay in the
  chain (it is part of the work and the client grades it), but it scores Right in the careful column.
- **Different results, different kinds of loss**, so different runs lose in different places: the strongest evidence
  a task is deep.
- **Mess may be a result** (an assembly or reconciliation result with its count and its gap to a control total), never
  the deciding one.
- **Breadth where it is natural**: many runs, units, series or files, so deciding what to look at is a result.

### 1.4 The chain does not hang on one result

The platform grades every figure against the golden, so a later result built on a wrong earlier figure is wrong,
whatever a carry-forward line says. A chain where one analytical result feeds most of the others through the chain
is one thing under another name. So:
- no analytical result carries more than half of the others (`precut.py` counts it; assembly, discovery and
  framing rows feed everything by nature and are not counted);
- give later results inputs of their own where the world allows: a bridge graded against the forecast file and the
  actuals, a monitoring rule graded on its alert count over a stated history, a flagged set graded on its evidence;
- the `Carry-forward:` line says which results stand alone and which fall with an earlier one.

### 1.5 The recommendation sits on top

Where the decision needs a call, it rests on several results, and the Final Recommendation names what the careful
but hurried pass would recommend and why it fails. A call that one result decides on its own puts the task back on
one thing: the call is one graded result among the chain, never the whole price.

## Part 2. The one-thing screen

### 2.1 The banned family

One hidden or planted thing that, once caught, flips the answer, in any of its forms (`CLAUDE.md`): rule application
(would the literal procedure give the answer with no judgment?), data semantics (would one sentence of clarification
make it routine?), a planted defect or decoy (is the hard part finding something rather than analysing it?), a
shallow hidden factor, a replay, a single-fact stump, an unpinned ambiguity. Several side by side are still banned.

### 2.2 The hidden factor record

For every pattern a solver has to find (a confounder, subgroup, contaminating event, timing break, measurement
change), the note's `## Hidden factor record` row says what it is, whether it is real or constructed, whether it sits
only in the deciding units, how it is found (one look, a targeted query, modelling) and how deep the fix is (routine
or modelling). Then:

- **Send-back (the client's three conditions together):** constructed; one sentence about it leaves one routine step
  (a stratification, an extra term, a filter, a reweight); easy to see once looked for (only in the deciding units,
  or one cross-tab or plot shows it).
- **Refused here whatever the fix:** constructed and only in the deciding units. A real process puts its effects
  across the data; an effect only where it decides was placed.
- **Thin:** constructed and fixed by a routine step but found only by modelling; it may be one of several results,
  never the one the call turns on.
- **Fine:** finding or correcting it is analysis (detection takes modelling or diagnostics, rival explanations have
  to be separated, the correction is a genuine modelling judgment), and it is one of several pieces of work.

In a generated world everything is constructed, so the record turns on the other two conditions: the factor shows
across the data the way the process would produce it (not only in the deciding units, never alone with no noise or
other patterns around it), and handling it takes modelling.

**Screen the form that misleads, not the family.** A row names the pattern in the form that sends the hurried pass
wrong, and counts two things: the units where the hurried route misreads, and the units where that misreading decides.
When every misreading decides, the factor sits only where it decides whatever the family's footprint. task6's
architecture 7 listed callers slowing late in five of seven incidents, a footprint that passed, while the form that
misled (a blocked caller ending further over its curve than the faulting service) sat in one incident, which alone
decided one service: the returned shape again. It was rebuilt with the form in three incidents, two deciding
different services and one deciding nothing, and `checks.py` asserts a misreading where nothing turns on it. **Calibrate on the client's seven designs** (the
deep-reasoning page's exercise): a 12 per cent dip added to the four control stores in the launch month, send back;
a public discharge file needing risk adjustment, shrinkage, a decomposition and intervals, keep; a churn flag
recoded in one region from the decision month, send back; a replaced river gauge found by comparing neighbours
inside a flood-frequency, persistence and return-level task, keep; a treatment that works only on one app version
present only in the last two treated weeks, send back; competing exits as the one hard step on public loan data,
keep but thin; survey microdata losing points at three different steps, keep.

### 2.3 The one-fact test, counted

Name the single most useful sentence a reviewer could give a run ("the meters changed in 2021", "that file is a
sample", "five of the stores also had a price cut") and count the results it rescues from the careful pass. A third
or fewer passes; more than half is a redesign. A legitimate method choice that is the hardest step does not fail the
test (nothing was hidden), but it makes the task thinner: build the results around it.

### 2.4 Our own record, read against it

task13 (Kotuku Networks, READY on 2026-11-09 under the retired design) shows all three readings at once. The storm
track swinging between the northern and southern stations was constructed and one plot of gust hours by station shows
it, but correcting for it is modelling (exposure per feeder from four hourly records), so on its own it is thin, not
banned. The plantation feeders' dense corridor was constructed, sits in the units that decide the six, and one cross
tab of interruptions against trim age gives it away, with one filter as the fix: a send-back. And every graded
figure came out of one Poisson fit, so the chain hung on one result. The rebuilt task would keep the weather work as
one result among several (a reconciled outage record, the exposure model, the regrowth rate with its band, the
catch-up's avoided interruptions, the quarter split, the range over the station record) with each graded on its own.

## Part 3. The effort test

### 3.1 Three passes

- **Quick** (ten minutes): the obvious file, the raw comparison, the first account that fits.
- **Careful but hurried** (an afternoon), calibrated to the run record, not the design: everything in Part 0's first
  list, stopping where a result needs a move beyond it.
- **Thorough** (two days, every number checked twice): the golden.

The client's thresholds, enforced: the quick pass earns about a third of the results or fewer; each pass earns
strictly more than the last; the thorough pass earns every result; the largest single hint rescues a third or fewer.
The careful but hurried pass's rubric score is the **pair estimate**, 50 or under.

### 3.2 Measured, not asserted

The generator implements the golden and each hurried method end to end on the cut pack and writes
`generator/effort.json`: every result's golden (tied to its `figures.json` key), band, partial band, dependencies,
and the value each pass files. `effort.py taskNN` grades the passes, prices them on the rubric split (the call and the
components 38, the asks 55, instruction-following 7) and prints the Effort test table; `--check-note` refuses a
design note whose table or pair estimate disagrees with the measurement. A hand grade carries its reason, and a
pass that misses a dependency cannot be hand-graded Right downstream of it.

**The paper is optimistic.** Mark measured paper ceilings of 35 and 39 that came back at 83, and the Sulfur runs
modelled every mechanism a plot showed. So when unsure, grade the careful column up, not down.

## Part 3b. The depth scale

`guidelines/client/depth-scale-2026-11-09.md` is the client's own reading of 17 real submitted tasks on five levels:
**1 lookup or rule-following** and **2 one-thing flip** are sent back; **3 one real method step** is a judgment call
(about half were kept: kept when the insight is real, needs estimating, runs through the whole dataset, is distinctive
and holds by a clear margin); **4 layered** (two or three connected judgments, each needing estimation) is the aim;
**5 difficulty throughout** (many independent judgments, different shortcuts landing on different wrong answers, the
answer holding across a sweep of variants) is the best. Learn from it; never template it: no build reuses an
example's setting, chain, trap, detection, fix or deliverable set ("reusing an investigation skeleton is a send-back").

**The level, in the note's `Depth level:` line.** Write down every step where a careful analyst has to choose; for each,
would a reasonable shortcut change the answer or the key figure? Tell the solver the key insight: if the rest is now
routine the task is at 1 or 2. If the hard part is something the data really show and it still needs estimating, it
is 3 or higher. If different shortcuts land on different wrong answers, it is 5: `effort.json`'s `routes` record each
shortcut's committed answer, and `effort.py` warns when fewer than two distinct wrong answers come out of them.

**Moving a task up a level** (the page's own moves): make the size of an effect, not only its existence, decide; add a
second independent judgment that also moves the margin, with its own checkable figure; widen the margin so no single
adjustment flips the call alone; show in the golden how each later step works from the earlier figures (a routes
table of each shortcut's figure beside the golden's) so careful partial work earns credit; spread the work over
different analysis types, not one investigation template.

**What the reviewers marked weak even at levels 4 and 5**, each a design or generator fix before the pack is cut:
- constructed data, noted on every generated example: the data behave like the real thing throughout
  (`dataset-generation` §2), and public data used as is is preferred where it fits;
- a built-in hidden factor even when it runs everywhere (the robbery surge at the start of the patrols);
- a generator setting visible in the data: a clean step at a round 60 minutes, a pattern too clean (one unit in every
  past launch); effects ramp, start at uneven times and carry noise;
- an idea hinted by a document (a legend's general warning, a comparability rule pointing at the break);
- a call that is easy once the central idea is seen, or a margin so thin the range nearly reaches the line;
- a figure that is the midpoint of two very different designs; deliverables so heavy the work sits away from the
  deciding step; a prompt that is hard to read.

**What they marked good:** real data with real export quirks; an insight from the field's own reasoning (the layout,
the physics, the survey design), then quantified and cross-checked against independent evidence; an AND ("two
independent method corrections are both needed; either one alone stays under 4.0"); different shortcuts naming
different wrong answers; a routes sheet showing each shortcut's result; a reference solution that sweeps reasonable
variants and holds; follow-up asks that use the completed intermediate result rather than read it.

## Part 4. The domain, used

The results are quantities the assigned field estimates, models or tests, worked the way its task types work them
(`guide-to-prompt/references/domains/`). Run the swap on the call sentence, never in the head: if it still reads
with a hospital for a substation, the domain is a backdrop. A sort, filter, join, threshold or stated score
deciding a result is a backdrop at any depth. In General Statistics & Data Science the swap is of the method: each
result is the analysis type's own statistical object.

## Part 5. What Mark measured, kept as cautions on every result

Each caution prices a result: a result it describes is earned by the runs.

- **The field's named method is the opponent's first move.** A result whose golden is the textbook method applied as
  the textbook states it is earned (139, 166, 156, 137, 133, 255, 273 and 464 were landed on it). The results that
  price the task are where this dataset breaks a precondition of that method, or where the method's output has to be
  carried somewhere the method does not go.
- **Anything written down is executed.** A filed sentence, helper document, release note or pin that names a
  result's step, clock, window, grouping or population hands that result over. Governing documents carry the WHAT in
  the organisation's own genre (a tariff, a reporting standard, terms of reference); helper documents describe
  fields, never process (124's verification narrative was solved the next day; 144's field notes were landed).
- **The WHAT is filed, the HOW stays open.** Each result's population, outcome, window, unit and comparison are
  filed so their literal execution is the golden; a step that settles one of them is a fork or a rule, never a
  difficulty (190, 192, 193, 269, 306 and 483 died there). If the sentence that would close a fork names what a
  result's work recognises, the fork is that result's difficulty and the result is redesigned (`determinism-check`).
- **A grouping cannot carry a result on its own.** Pooled against stratified either shows in the fit (taken by
  reflex) or forks the answer; heterogeneity prices a result only through what the decision does with the groups
  (weighting them to the population the decision serves).
- **A mechanism the rows visibly carry is modelled on sight** (Sulfur, five rounds).
- **Devices whose discovery is their remedy are work orders.** The hygiene battery prices nothing.
- **Distractors** (two or more files the solution never reads that look worth weighing) are named only in
  `metadata.json`, never carry a result, and never bind a graded figure when read literally. **Voices** are optional,
  at most two people with beliefs, never a roll call, never a belief pointing at a hurried answer. **Context
  artifacts never rank the candidates** (Gate G).

## Part 6. The design note and `precut.py`

The note follows `references/design-note-template.md`: `## Draw` (analysis type, answer shape, weight, data-native
sentence), `## Deep reasoning` (one labelled line per point), `## Results chain` with its `Carry-forward:` line,
`## Hidden factor record`, `## Effort test` (`Measured by:`, `Largest single hint:`, `Pair estimate:`), `## Data
provenance`, `## Template check`, `## Semantic fork table`, `## Closure table` (22 axes), `## Literal reader`,
`## Prompt contract`, `## Tried and rejected`.

```
python3 .claude/skills/stumping/precut.py taskNN      # stage 2 exit, and again on the final cut
python3 .claude/skills/stumping/effort.py taskNN      # once generator/effort.json exists
```

`precut.py` refuses a missing section or label, fewer than four results or three areas, a result with no band, pin
or answer block, a hurried failure outside the six deep classes or one the runs do not make, an analytical result
carrying more than half the others, a refused hidden factor, an effort table that fails the thresholds or disagrees
with `effort.py`, generated data with no account of how it behaves like the real thing, and the same chain and
answer shape as a build on file. It runs `voice-check.py` on the prompt. A build cut under the retired design is
checked on its old contract with a warning, and is re-rooted before any re-ship.

## Part 7. The draw

**The card first.** `guard.py recent`, `coverage`, `mechanisms --objective <analysis type>` and `slots` on both the
mechanism's nouns and the setting's (`fingerprint` Part 2). The card carries `objective` (the assigned analysis
type), `answer_shape`, `weight` and `chain_signature` (the areas of the results in order); `guard.py check` blocks a
chain and answer shape repeated anywhere on file, the weight of either of the last two builds and the answer shape
of the last one, then `register`. Personas from `guard.py names`.

**Where a chain comes from.** Read the client's strategies for the domain group (`references/sulfur-strategies.md`
points into the export): each names its analysis type, answer shape, where the weight sits, the chain of hard
results, the public data where that work already lives, and its own shallow twin. Copy the lesson, never the shape:
"A lesson can come back in a new task. A structure cannot." Then write the chain from the process of this world
(1.1), and expect the results the runs will lose to be the ones Part 0's second list names.

**The abstraction sentence**, written into `## Template check`: the one sentence a reviewer holding this build and
its nearest build on file would say is the same, written without domain nouns. If it can be written, redraw the
weight or the answer shape. The portal wrote exactly that sentence for Mark's 175 and 179.

**The shell is drawn too.** The prompt's question form, the deliverable set and the answer shape are what a
reviewer reads first: the prompt discloses no count the data hold, the batch quotas in `voice-check.py --all`
hold, and a re-root redraws the shell with the world.

## Part 8. Diagnosis and repair

A diagnosis comes from the platform's runs or the judge, never a solve in the main thread. `/triage-runs` maps each
run's losses result by result:

- **Losses spread across results, analytical classes, average under 60**: submit.
- **Average 60 or more, losses analytical but few**: the chain is too easy where the runs earned it. Move the weight,
  add results that need their own work, or rebuild an earned result around a move beyond the runs' reflexes; never
  harden by planting, never add a rung above a solved step.
- **A result lost to a surface class** (a missed plant, a shallow factor, a reading, a procedure): rebuild that
  result on real analysis, or make its trigger texture off every graded path.
- **Most of both runs' lost weight on one result**: thinner. If that result turns on a built-in factor, it is a
  send-back in waiting; redesign before the reviewer reads it.
- **A defensible alternative on a result**: `/fix-determinism`; widen the band to what the honest family shares, or
  file the WHAT the alternative read differently.

**Re-root rules.** One architecture per world: once a world's chain is spent, the next draw moves to another world,
another dataset and another shell. No same-day serial re-roots without new evidence. One mechanism per repair, the
dead end written in `## Tried and rejected` when it dies.

## Part 9. What is dead

Everything in the banned family, and the single-deep-step design itself: a task priced by one hidden step with a
ladder beneath it, however deep the step (tasks 1 to 14, returned in kind by the 2026-11-09 review). From Mark's
record, as results: the field's named method as the golden; a quantity a sentence, helper document or schema names;
a column one join away; a reflex; a control that nominates or refutes; a filed rule over filed candidates; a dated
cutover as the answer; a validated decoy; a grouping alone; an estimator family with nothing in the data to close it.
`references/sulfur-strategies.md` labels every strategy; `strategies.md` Part 6 and `evidence.md` carry the
measurements.
