What a strong package contains
▾
Clear every line below.

Multiple input files. At least 10 real, usable files, usually 10 to 30. System files such as .DS_Store, __MACOSX folders and empty placeholders do not count.
Diverse files. At least 2 distinct file categories. Archives do not count toward diversity, but the files they contain do.
Spreadsheet: .csv, .xlsx, etc.
Database: .db, .access, etc.
Text: .txt, .md, .docx, .pdf, .html, etc.
Image: .pptx, .png, etc.
Code: .py, .cs, etc.
Large, messy files. At least 2 input files must be large and messy, for example a CSV with 20,000+ rows and a long multi-page report or spreadsheet. Both carry realistic mess (see Realistic messiness below) that the model has to explore, clean, and reconcile.
Cross-referencing. The task should require understanding across files.
Realistic messiness. Input files should include realistic noise, such as missing values, inconsistent formats or timestamps, ambiguous column names, or duplicates. Do not pre-clean files to the point where analysis is trivial, and do not make the noise so extreme that no deterministic recommendation can be derived. Cleaning is texture: it must never be what decides the answer.
Distractor files. Include at least 2 distractor files. A distractor is not needed or used in your solution but looks like it might be useful, so the model has to consider whether it is useful. A completely unrelated file is not a distractor; it must look relevant. Never label a distractor, in its file name or anywhere else inside the ZIP.
Fragmented data. Data can be spread across files and include template files, historical reports, and so on, that the model has to explore to understand. Real packages often hold the same report at different dates; that is fine as texture, but picking the right version must not be what decides the answer.
Nothing that gives the build away. No LLM-generated files, no notes on how the task was made, and no file whose only purpose is to carry a trap.
The data sets up the problem. What decides the answer is the analysis on top of it: see Deep reasoning.
