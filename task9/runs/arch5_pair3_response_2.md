Assumptions and judgment calls.
Latest quarter-end snapshot = 21 September 2026, the latest snapshot closed at a 23 November 2026 assessment; 21 December 2026 has not occurred. The labelled-row plan’s “Book Dec 2027” is treated as a forward-looking sensitivity, not the standard’s latest actual snapshot. Using it flips no placement, so the call is insensitive to this choice.
Assessment date 23 November 2026, the latest weekly refresh in the records; figures are committed estimates on filed inputs, not realized 2027 outcomes.
“2027 weekly retrains” = ISO 2027 family-weeks, 52 weeks × 14 families = 728, equal weight per family-week (not scored merchants, accelerator hours, nodes or book). The covenant pair-year reading (28 December 2026–20 December 2027) is reported separately because it is the standard’s assessment window; it gives a lower count (445/728) but the same adoption dates and the same feature-release placement.
Pinned adoption is projected from first observed production use, median of the three prior changes’ planned→first lags, because the prompt/calendar supply only a planned week for PC-26-058 and scheduler history is the only evidence of actual behavior. Rollback/re-enable cycles are not projected; the permanent-adoption sensitivity bounds them (58.9286% ISO, releases 6.7521, still Remediation). A reasonable committee could choose completion-date anchoring (65.1099%, releases 6.0442, still Remediation); only treating the filed schedule as actual flips releases to Monitor.
Warm-start read as full 13-week accumulation, no decay/rho, because §1.4 states prior randomness carries and supplies no parameter. I examined panel time-series behavior but did not impose an unstated decaying-persistence model on the placement arithmetic.
Per-refresh instrument MSE used as the source’s expected weekly mean-square effect, including treating replicate/label/retune/release pair MSE directly and only turnover-scaling bootstrap. The workbook discloses this and the GAME raw-vs-effective example.
Release in the week pinning begins is suppressed, per §1.5’s “in the weeks a family trains and scores on pinned views.”
Score-change distribution zero-mean Gaussian, constant variance per family/pair, applied to the 21 September 2026 panel held fixed; future attrition/new panel draws not projected. Tiers fixed at 400/500/600. Heavy tails or heteroskedasticity would move tier shares but not placements.
Own change carried as the standard’s single aggregate (74.128653 MSE) for the headline covenant figures; family-residual carry is shown as sensitivity (13.5741/6.0422) and changes no placement or cap conclusion. Reported own share uses 2027 sources, per §5.2.
Panel score duplicates superseded by later load_id; quarter-end cells had no duplicates, so this affects diagnostics/validation, not snapshot inputs. Latest panel used post-migration IDs; 2026 snapshots already used new IDs, so Tolka handling changed no covenant count.
Retune cadence assumed to persist every 28 days; the standard provides no 2027 retune plan, so this is a projection, not a filed fact.
KPI/performance and PSI drift files were inspected and not used, because no §3 movement, §4 band, §5 share or §6 tier computation consumes AUC/calibration/Brier or PSI; using them would import an unstated adjustment.
2024–25 panel regimes were not pooled into 2026 instrument evidence, because platform rollout (image/warm-start/precision) completed at staggered dates and MRM pairs are current-regime evidence.
